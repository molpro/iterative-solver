Detailed Description

template<class R, class Q, class P>
class molpro::linalg::itsolv::detail::MetricChecker< R, Q, P >

Checks that the metric of a generalised problem has the properties that its kind declares, as far as the subspace shows them.

All checks throw std::runtime_error if they fail. They compare against hermiticity_tolerance() or positivity_tolerance() relative to the size of the quantities involved.

Checks that the metric is Hermitian on new parameters before they are added to the subspace.

The metric matrix is calculated from the actions of the metric on new parameters only, assuming that it is Hermitian. This compares <x|M q> with <M x|q> for the new parameters x and a vector q of an earlier update: the most recent Q vector if the subspace keeps the actions of the metric, otherwise the first parameter of the previous update, kept by remember().

Checks that the metric matrix of the subspace is consistent with a positive (semi)definite metric.

The metric matrix M_ij = <b_i|M b_j> of a positive definite metric M is positive definite for linearly independent subspace vectors b_i, which a Cholesky factorisation confirms cheaply. Where it fails, which nearly linearly dependent subspace vectors can cause as well, the Rayleigh quotients of M on the span of the subspace vectors decide. They are the eigenvalues of the metric matrix in the basis orthonormalised with the overlap S_ij = <b_i|b_j>, leaving out nearly linearly dependent directions. Orthonormalising amplifies the rounding errors of the metric matrix by up to the inverse of the smallest eigenvalue of the overlap that is kept, so the metric fails the check only if a Rayleigh quotient is negative by more than positivity_tolerance() times the largest plus these amplified rounding errors.

An indefinite metric is noticed only once one of its negative directions enters the subspace.

Parameters
metricthe metric matrix of the subspace
overlapthe overlap matrix of the subspace vectors

Like check_positive(), for the metric matrix of the subspace, whose first nP rows and columns, those of the P space, do not change between calls until reset_pspace()

The Cholesky factor of the P-space block is kept, so that only the Schur complement of the other vectors has to be factorised, at a cost of nP^2 times their number, rather than the whole matrix. If that fails, check_positive() decides.
