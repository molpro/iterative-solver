gemm between distributed arrays xx, read through a BufferManager, and arrays yy, which can be held anywhere.

Only the local section of xx is processed, chunk by chunk. For each chunk of global indices [g, g+n), y_pointers(g, n) returns pointers to the same elements of each of yy, and y_done(g, n) is called once the chunk is complete, e.g. to write back yy updated by gemm_type::outer.

Parameters
alphadatasee gemm_chunk(), with nx = xx.size() and ny the number of yy

One chunk of n elements of a gemm between the arrays xx, which are the nx columns of x with leading dimension ldx, and the arrays yy at pointers y.

inner: alphadata[i + k * nx] += x_i . y_k outer: y_k += sum_i alphadata[i * ny + k] * x_i

This is a single dgemm. If yy are not evenly spaced, they are first packed into one matrix, which an outer product then updates before it is copied back.

template<class AD , class T = typename AD::value_type>

const VecRef< AD > &  yy 
)

yy += alphas^T xx, for arrays xx held in memory and distributed arrays yy held anywhere.

Only the local section of yy is processed, in pages. Pages of yy without a local buffer are read with get() and written back with put(), so that each element is read and written once. x_bases are pointers to the starts of the local sections of xx; unless they are evenly spaced, each page of them is first packed into one matrix, so that the update is always a single dgemm.
